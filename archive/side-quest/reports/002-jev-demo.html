The problem

Three people, one stream of logs, three different questions.

EngineerWhat broke, and where?
Team leadHave we seen this before?
ManagerWhat do we fix first?

3.9 million log lines a day. Even a quiet 15 minutes has about 220 errors.

Can you spot the real fault?
What Jev does here

SereneDB says what changed. Jev says what it means.

Noulyes / no
Choiceone of many options
Scorea level on a scale

It reads the log lines SQL selected and picks a meaning: which fault, which service, same problem or not, which to fix first.

No keyword lists. No training data.About 0.25 s, the same answer every time, with a probability you can set a threshold on.

Where Jev is not needed

Use Jev only where meaning is needed.

Most decisions on GAIA can be made by code alone. Taking Jev out of them loses nothing.

73% of questions need no model at all.The real gap sits in one small group.
Technique 1 · evidence

Show Jev only what changed.

Jev reads every line literally. Show it routine errors and it reports them as faults.

All errorsevery error pattern in the window
Only changesnew, or 2× the service's usual rate
Jev 0.34 → 0.80The biggest gain came from SQL, not the prompt.
Technique 2 · numbers

Do the math before Jev sees it.

SQL computes the ratio. Code turns it into a phrase.

"About 2x its usual rate", not "22 vs 10".We tested removing the raw counts too: Jev's answers didn't change. The phrase is what it reads.
Technique 3 · structured options

Define each option, including what it is not.

Each option carries a definition, what it covers, and what it does not.

+0.05 for Jev in experiment 001.
Technique 4 · evidence-in-choices

Let the data supply the options.

The options are the evidence items and the services, each described by SQL. Jev picks one. Nothing is invented.

Root service right on 100% of dev faults.On GAIA a code rule (earliest error spike) matched it. The pattern pays off when candidates really compete.
Technique 5 · abstain

Let Jev say "cannot tell".

A Choice always picks something. Give weak evidence an honest place to go.

Jev 0.80 → 0.87Its best single question change.
Technique 6 · two steps

Splitting a question doesn't always help.

First "is there a fault?", then "which kind?". Code multiplies the two.

No gain here: 0.79 vs 0.80.Measure every design before keeping it.

Field notes

Nine rules for using Jev.

SereneDB says what changed. Jev says what it means. Code decides the rest.

Let code decide what it can.Ask Jev only what needs meaning.
Filter before you ask.Only what is new or unusual.
Turn numbers into words.Let SQL do the math.
Define every option's edges.Covers / does not cover.
Make the data the options.Evidence ids, services.
Offer an honest exit."None" or "cannot tell".
Ask many narrow questions at once.One request, parallel answers.
Swap the option order.A stable answer survives it.
Compare with an LLM on identical input.Keep only what beats noise.
