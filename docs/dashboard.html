Run the evaluation yourself

The questions, the answer keys and the judge are all in the repo. Each answer key holds the true answer, the SQL that established it, its result, and the traps to avoid. Keys were written by agents without context, from raw SQL and Loghub's labels.
# 1. SereneDB with the datasets the questions use (base corpus + the 8 others)
docker compose up -d
uv run python -m loader load base            # BGL + OpenStack
uv run python -m loader load zookeeper       # … apache, ssh, hdfs, linux, healthapp, otel as needed

# 2. Keys: ANTHROPIC_API_KEY in .env (agent = AGENT_MODEL, judge = JUDGE_MODEL, default Opus)
uv sync --extra agent

# 3. The A/B: our product agent vs the brief's reference ReAct agent, same MCP tools, blind judge
uv run python -m eval.ab --arms product,baseline                 # all 50 questions (~45 min, concurrency 5)
uv run python -m eval.ab --arms product,baseline --ids D-E01,D-L04   # a smoke test on 2 questions
uv run python -m eval.ab --rejudge eval/results/ab-<stamp>.runs.json  # re-judge stored answers only

# 4. Rebuild this page from the new result
uv run python scripts/build_dashboard.py

Files: eval/dev_questions.yaml (questions + golden facts) · eval/answer_keys/*.yaml (50 keys) · eval/ab.py (runs, blinding, judge, report) · eval/results/ab-*.md|json|runs.json (reports, scores, full answers + evidence). How the judge stays blind: tool names and evidence ids are stripped from both answers, a leak scan stops the run if any remain, and the order of the two answers is random and seeded.
